## Go API

The Go API uses focused `internal/` packages: handlers do not contain persistence code and provider SDKs are isolated behind repositories/adapters. It uses GORM with PostgreSQL for its database layer.

## database:neon

Use the pooled `DATABASE_URL` (the hostname includes `-pooler`) for application traffic and the direct `DATABASE_URL_UNPOOLED` for migrations. From `backend`, run `go run ./cmd/migrate` before `go run ./cmd/api`. Official guidance: https://neon.com/docs/connect/connection-pooling.

## Google Cloud Storage provisioning

Run `scripts/provision-gcs.ps1 -ProjectId YOUR_PROJECT -Bucket YOUR_BUCKET`, or `bash scripts/provision-gcs.sh YOUR_PROJECT YOUR_BUCKET`. The scripts use the `gcloud` CLI and Application Default Credentials.

## email:twilio

Use Twilio Email—not SendGrid—at `POST https://comms.twilio.com/v1/Emails`. It is asynchronous and returns an operation ID; use the operation location to track delivery. Official guide: https://www.twilio.com/docs/email/api/overview .

## organizations

Organizations is selected in the generator metadata, but it is not implemented in this starter yet. There are currently no organization models, migrations, repositories, routes, invitations, or role checks.

## Docker

`docker compose up postgres` starts the local PostgreSQL dependency with a health check.

## Continuous integration and deployment

GitHub Actions runs Go vet/tests and frontend tests/builds for every pull request and push. A successful push to `main` can deploy the backend to Cloud Run after you configure GitHub OIDC federation, Artifact Registry, and Secret Manager. Follow [the deployment setup guide](docs/github-cloud-run-deployment.md); it uses short-lived Google credentials rather than a service-account key.

## Security

Never commit the .env file. Use managed identities where supported and set production-only secure cookies.
